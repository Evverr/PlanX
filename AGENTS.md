# PlanX: правила для ИИ-помощников

Этот файл читают все, кто пишет код в PlanX: Codex, Claude в облаке и Claude Code в VS Code.
Истории разговоров друг друга мы не видим, поэтому важные решения записываем сюда.
История проекта, решения, риски и планы — в `docs/HANDOFF.md`. Прочитай его перед первой задачей.

## Кто есть кто

- **Женя (Zheka, GitHub `Evverr`)** — владелец проекта. Ставит задачи, пробует результат руками и решает, что сливать в `main`. Не разработчик: пиши по-русски, коротко, что нажать и что ввести, а не как устроен git.
- **Codex** — основной разработчик. Делает задачи в своих ветках `codex/<коротко-о-задаче>`, сам проверяет их (см. «Проверки») и открывает PR в `main`.
- **Claude (облако)** — с 30.10.2026 больше не основной помощник. Если Женя позовёт, делает задачи в ветках `claude/...`.
- **ВижуалКлод (Claude Code в VS Code у Жени)** — мелкие правки внешнего вида прямо в `main` на Маке.

## Как работаем

1. Перед началом работы возьми свежий `main`.
2. Одна задача — одна ветка — один PR в `main`. В `main` напрямую не пушь (это делает только Женя через ВижуалКлода).
3. Перед PR сам прогони проверки по размеру задачи (ниже): отдельного ревьюера нет. В описании PR по-русски: что сделано, какие проверки прошли и как это попробовать руками.
4. Замечания из ревью исправляй новыми коммитами в той же ветке, историю не переписывай.
5. Сливает PR только Женя.
6. Vercel сам собирает превью каждого PR и пишет ссылку в комментарии: по ней Женя пробует результат.

## Проверки

Объём проверок зависит от размера задачи. Не трать время на лишнее: Женя ждёт результат.

**Мелкая правка** — цвет, текст, отступ, подсказка, правка в одном файле стилей или README. Полные проверки не нужны. Если менялся `.ts`/`.tsx`, хватит `npm run typecheck`; если только `.css` или текст, можно ничего не запускать. Женя сразу смотрит результат на localhost.

**Средняя и крупная задача** — новая функция, логика, несколько файлов, всё в `src/model`, `src/collab`, `server/`. Прогони всё:

```bash
npm test           # vitest
npm run typecheck
npm run build
```

Все три должны проходить. Тесты не отключай и не пропускай, чтобы получить зелёный результат. Кодекс прогоняет их сам перед каждым PR (кроме мелких правок) и пишет результат в описании PR. Если меняешь логику, добавь или обнови тест в `tests/`.

Перед PR также сам перечитай свой дифф по правилам этого файла: новая функция в `src/labs` с переключателем, нет файлов, отличающихся только регистром, нет новых зависимостей без нужды, изменения данных сливаются у нескольких людей.

**Работа ВижуалКлода в `main`.** Мелкие правки коммить локально без проверок. Пуш — это веха: перед ним один раз прогони полные проверки (`npm test`, `npm run typecheck`, `npm run build`) и почини, если что-то сломалось. Пушь, когда Женя просит, перед тем как дать задачу Кодексу или облачному Claude (они видят только запушенное) и в конце рабочего дня.

`npm install` нужен только если менялся `package.json` или папки `node_modules` ещё нет.

## Экономия времени и токенов

У Жени ограниченный тариф, каждое лишнее действие стоит денег.

- Читай только файлы, нужные для задачи. Не обходи весь проект «для контекста»: структура есть в `README.md`.
- Мелкую правку делай сразу, без плана, браузера и e2e-тестов.
- Отвечай коротко: что сделано и что нажать. Без пересказа кода и длинных объяснений.
- Не переспрашивай, если задачу можно понять однозначно; при сомнении выбери самый вероятный вариант и скажи какой.
- Не запускай одну и ту же проверку повторно, если код с тех пор не менялся.

## Проект

Доска для планирования в духе Miro, весь интерфейс на русском. Подробности и структура папок — в `README.md`.

- TypeScript + React, отрисовка доски на `<canvas>`.
- Данные доски в Yjs (CRDT), отдельно от отрисовки: `src/model`. Каждый элемент — свой `Y.Map`.
- Совместная работа с самого начала: свой сервер синхронизации (`server/`), офлайн-кэш в IndexedDB, курсоры участников (`src/collab`). Любое изменение данных должно корректно сливаться у нескольких людей сразу.
- Стартовая страница «Мои доски» с полками и папками: `src/shelf`. Шаблоны: `src/shelf/templates.ts`.
- Продакшен: https://planx-ten.vercel.app

## Правила, о которых легко забыть

- **Новые функции — пробные.** Новая функция кладётся в `src/labs` и получает переключатель в меню доски «Нововведения» (список `LABS` в `src/labs/labs.ts`, проверка `labOn(id)`). Так Женя пробует её и решает, оставить или убрать. Убрать = удалить её файл и строчки с `labOn`.
- **У Жени Mac, файловая система не различает регистр.** Никогда не делай два файла, имена которых отличаются только регистром (например, `Labs.tsx` рядом с `labs.ts` ломает сборку).
- **Иконки** — свои SVG 24×24 в `assets/icons`, только заливка, без обводок. После изменений: `npm run icons` (пересобирает `src/icons/icons.json`). Цвет `#333333` становится цветом иконки.
- Пиши код в стиле окружающего: те же имена, та же плотность комментариев.
- Не добавляй зависимости без нужды; версии в `package.json` точные.

## Проверка работы Кодекса

Обычно Женя просто смотрит превью Vercel и сливает PR сам. Если Женя просит ВижуалКлода «проверь PR Кодекса», порядок такой:

1. Сделай `git fetch` и найди самую свежую ветку `codex/...`, которая ещё не слита в `main` (или PR с номером, который назвал Женя).
2. Расскажи Жене простыми словами, что в ней изменилось.
3. Проверь, что изменения соответствуют правилам из этого файла, и прогони проверки по размеру задачи (раздел «Проверки»).
4. Если есть проблемы, не исправляй их сам: напиши Жене списком, чтобы передать их Кодексу.
5. Если всё в порядке, переключись на эту ветку, чтобы Женя посмотрел результат на localhost.
6. После «ок» от Жени слей ветку в `main` (через `gh pr merge`, а если `gh` нет — `git merge` и `git push`), вернись на `main` и сделай `git pull`.
